### Q13. 映射到经典软件工程设计模式？

属于什么模式吗？就是就是 hook 的原理嘛，就是及时的去调用外部的工具然后这边先 expand 一下然后把 hook 结果拿回来再继续推进主流层，这种设计思想。

> **AI**：你描述的本质是**拦截器链模式（Interceptor Chain / Filter Chain）**——多个 middleware 按顺序注册到 ReAct 循环的六个 Hook 点，每个 middleware 都可以做前置处理、后置处理、甚至阻断流程（如 HumanInTheLoopMiddleware 暂停等人工审批）。这也融合了**模板方法模式**——ReAct 循环是算法骨架，六个 Hook 是预留的扩展点。但**不是观察者模式**——观察者只能被动接收通知，不能修改数据或阻断流程；middleware 可以。如果面试官期待传统 GoF 答案，最接近的是**责任链模式 + 模板方法模式**的组合。

### Q18. LangChain/LangGraph 的模块设计？

（这个我卡了好久，因为我不知道什么叫模块，有点不知道他想问什么，我还确认了一下是不是核心组件，他说不是，是模块）

模块设计，LangChain 来说的话怎么说呢就是它做了一些核心组件的封装，然后去就是你说模块方面的设计是指他可能细分成哪些子模块然后模块之间是怎么去比如说通信啊或者是调度啊就是这种。那应该是比较偏向于 LangGraph 一点，因为 LangChain 它本身比较高层。LangGraph 的话它比较它是基于图的一种结构，比较方便去编排子模块。然后这个 LangGraph 里面它每个节点相当于一个 Python 的函数然后它执行的每个超步里面它可以在这个节点里面再弄一个子 agent 小模块在里面，然后做上下文隔离。然后里面的子 agent 去完成一些工作最后只返回一个结果的摘要。然后给大这样就不会把上下文撑爆了，然后就这种工作模式。然后整体的模块的话就是类似于按照图去设计吧，第一次我拿到需求的话我先看要分成多少步去做然后每个部分去设计 node 然后再用图连接好再去渲染，这样一个过程。

> **AI**：这道题你卡住是因为没理解面试官说的"模块"是什么意思。你确认"是不是核心组件"，他说不是——说明他不是在问 Agent、Chain、Tool 这些**横向的功能组件**，而是在问**纵向的包/层级结构**：LangChain 的代码是怎么分层的、哪些是基础抽象层、哪些是社区集成层、哪些是上层编排层。

**面试官想听到的答案**：

LangChain 的模块分为四层：
- `langchain_core`：最底层，定义整个生态共享的抽象——`BaseLLM`、`BaseChatModel`、`BaseTool`、`BaseMessage`、`Runnable` 接口。所有上层模块都依赖它但不能反向依赖。
- `langchain_community`：社区集成层，包含所有第三方 LLM 提供商、向量库、文档加载器的具体实现。这层和 core 之间用适配器模式解耦。
- `langchain`：面向用户的高层 API，包含 Agent、Chain、Retriever 等编排组件，依赖 core 但不依赖具体社区实现。
- `langgraph`：独立的图编排模块，提供 `StateGraph`、`MessageGraph`、`Checkpointer`。它和 langchain 并行——LangGraph 的 Node 可以是任意 Runnable（包括 LangChain 的 Chain），但 LangGraph 本身不依赖 langchain。

各模块之间的依赖方向是单向的：`community → core ← langchain`，`langgraph → core`。这种分层设计让 LangChain 生态可以独立升级 core 而不影响上层。

**你说的是"图里节点怎么编排"，面试官问的是"包怎么分层"——两个维度完全不同。下次遇到不理解的术语，可以反问"您说的模块是指包结构/代码分层，还是指功能组件的组合方式？"**
