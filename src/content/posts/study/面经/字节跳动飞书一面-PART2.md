## 问题

### Q1. 大模型训练管线包含哪些环节？按你的学习结果整体介绍一下

好的，那我就讲一下昨天的学习过程吧。昨天面试主要说的是后训练的那两个过程，前面我忽略了预训练和中训练，还有后面更新的环节。

首先模型的预训练是通过一个大规模语料进行无监督学习，主要学习目标是 next token 的 loss。比如以前的 GPT-2，它就用了 BookCorpus 这种大规模语料库，可能来自网页或者书籍，包含大量自然语料。训练的时候只要让它预测下一个词的概率就行，目的就是让大语言模型学会基本输出语言，然后了解一些基本世界知识。

我们需要采集大量数据，不管从网页也好、wiki 也好，采集大量数据之后，先去重，然后脱敏、清洗，之后就可以分词。我们将语料分成 token 级别，然后映射到一个词表。这样接着训练的话，就可以训练这个词表。我们用 token ID 映射出一个稠密向量，然后加上位置向量，放进 decoder-only，现在大部分都是 decoder-only 的 Transformer 块里面，进行训练更新参数。最后会得到更新好的 LM head、QKV 矩阵、投影矩阵、全连接层参数，包括词表向量都会同步更新。这样预训练结束之后，我们就得到一个 base model。

之后就是中训练。其实也是跟预训练差不多，进行 next token 训练，但是可能会更偏向专业领域。比如之前面同花顺的时候，他们说做垂直金融项目会用自己的用户数据做中训练。这个方面会对特定领域、专业领域能力，数学能力、金融能力这些进行训练，加强模型在特定领域的表现。这个是中训练过程，技术上跟预训练应该差不多。

之后就是上次提到的后训练。后训练第一个阶段大部分都是 SFT，监督微调。因为经过预训练和中训练之后，模型只是掌握了如何说话，但是不知道怎么听你的指令。SFT 会预设几个角色，然后你在 system message 里面给指令，让模型学习怎么按照你给的 assistant 里面的语言去输出，这样它就可以学会从指令到输出。

但是只是 SFT 的话，模型还是不能知道哪个更偏向于你需要的答案，它只是会输出一个可能是训练当中看到过的一种答案。所以后面还需要进行强化学习。DPO 就是一种比较简单的离线强化学习方式，把 rejected 和 chosen 两个量离线标注好之后，对大模型进行强化学习训练，然后让大语言模型更倾向于把用户更满意的回答排在前面。

最后，目前最新的一些开源模型还会进行一些可验证的强化学习，也就是 RLVR 这种步骤，进一步纠正它的通用能力，让通用能力恢复到一个好一点的水平吧。后训练之后还有上线过后的迭代，也就是需要用户上线之后提供反馈。拿到这些反馈之后，可以再放进训练集或者相关数据当中，再次进行一些训练。当然这个过程也需要脱敏、去重、清洗，甚至需要人工标注之类的。这就是我昨天大概看的一整个大语言模型训练管线。

> **AI**：比 PART1 明显进步，至少把预训练、中训练、后训练、RLVR、上线反馈都串起来了。几个点要修正：① 预训练更准确说是自监督学习，不是普通无监督；② GPT-2 主要训练语料是 WebText，不是 BookCorpus；③ SFT 不是只靠 system message，它本质是 instruction-response 监督信号；④ DPO 更准确是离线偏好优化，不是传统强化学习；⑤ RLVR 不是为了"恢复通用能力"，更常见是用可验证 reward 强化数学、代码、推理等可判定任务。整体已经能讲，但基础术语还要更稳。

### Q2. 什么是 token？为什么要 tokenizer？

好的。首先 token 这个词元的概念就是说，我需要把一些高频出现的部分单独映射成一个 ID，我们把这叫 token ID。然后我们需要通过这个 ID 去定义一个高维度的 hidden state。

这样的话，我们就可以在一个词表内，有一定的 token 数，然后把每个句子进行拆分。有不同的拆分策略，比如之前的 BPE。总的目的就是尽量把高频的部分抽取出来放在一个表里面。以后遇到新的句子或者文本时，可以把句子拆分成一个一个 token，然后去查表，直接得到这段文本的稠密向量，这样就可以放到向量空间里面，然后进入 Transformer 块。

> **AI**：回答方向对，但 tokenizer 和 embedding layer 的职责混在了一起。Tokenizer 负责 `text -> token ids`，embedding table 负责 `token ids -> dense vectors`。这句话一定要背熟。更标准地说：tokenizer 把连续文本离散化成有限词表中的 token 序列，使模型可以在固定词表上学习概率分布。

### Q3. “我喜欢中国”按照 tokenizer 会划分成多少个 token？怎么划分？

如果是词表比较大的话，应该会划分成"我"、"喜欢"、"中国"，还有句号这几个部分，应该是这样的。

> **AI**：这个只能作为直觉，不能当确定答案。实际 token 数取决于具体 tokenizer 和词表。中文里有的 tokenizer 会按字切，有的会把高频词如"喜欢"、"中国"合并成 token；标点也可能单独成 token。更稳的回答是："要看 tokenizer，比如 BPE/SentencePiece/tiktoken 的结果可能不同。"

### Q4. 它怎么知道“喜欢”是一个 token？

一开始文本肯定都是一个一个字的 token。后来因为"喜欢"经常高频率出现在训练语料中，所以 tokenizer 的时候就会把"喜欢"聚合到一个高频词语，作为一个 token 来用。这就是词表的作用。原理上应该就是这样训练出来的。

> **AI**：核心直觉对：高频相邻片段会被合并。可以补得更准确：BPE 从字符/字节级别开始，反复统计最常共现的相邻 pair 并合并，直到达到词表大小；SentencePiece/Unigram 则是用概率模型选择子词，但目的都是用有限词表高效覆盖文本。

### Q5. 什么是有监督学习、无监督学习？假设我是初中生，怎么解释？

监督信号来说，应该就是有一个固定答案，然后我们去给它标注，让它往你标注的方向去做。比如在微调中，我们会设置一个标准答案，手工标注让大模型学习它。

无监督微调就是不需要人工标数据，直接把数据扔给大语言模型，按照某一种规则让它直接学习。可以这么说，这个监督是基于人的角度来说的：一个是需要自己标数据，一个是不需要标数据。

生活中的例子，我想一下。有监督学习就相当于我让你去超市买某种东西，我提前把这个东西的名称、商品编号都给你，你就去买这个东西。无监督学习的话，就是让你去商店买某类东西，比如让你帮我买一个零食，只要符合这个原本要求就行，不需要额外指定到底是什么商品。

> **AI**：解释得有点绕，例子也不够贴切。"买某类东西"其实仍然有目标约束。更适合初中生的说法：有监督学习像老师给题目和标准答案，学生对照答案改错；无监督学习像给学生一堆照片，让他自己把相似的分成几类，没有老师告诉每张照片是什么。LLM 预训练更常说自监督：答案来自文本自身，比如用前文预测下一个 token，不需要人工标注。

### Q6. SFT 和 DPO 的区别是什么？也可以用初中生视角解释

SFT 和 DPO 的区别，如果直接从大语言模型方面讲，SFT 是让大模型学习指令遵循能力，或者某一种风格能力。它的目的是让大模型能听懂你让它做什么事，而不是只是机械地接下面的文，因为预训练是让它机械地学习预测下一个字是什么。

这样的话，它有了一定指令遵循能力。而 DPO 包括后面的强化学习，面向的主要是用户这个方面。因为 DPO 会进行离线标注，把我偏好的数据标出来。可能两个回答都是合理的，但是我更偏好 A。那这种情况下 SFT 就做不到了，我就需要用 DPO 把我更感兴趣的回答的生成概率放大。

所以 SFT 和 DPO 一般是前后的关系，就是先进行 SFT，再进行 DPO。

> **AI**：这个回答不错，能用。更精炼的面试版：SFT 是"老师给标准答案让学生模仿"，DPO 是"老师给两个答案，说更喜欢哪一个，让学生以后更倾向这种答案"。技术上，SFT 用 instruction-response 做监督学习；DPO 用 chosen/rejected 偏好对，让 policy 相对 reference 更偏向 chosen。

### Q7. 你了解过 Transformer 架构的基本原理吗？

了解过，因为 Transformer 是比较经典的架构，看过原论文和一些架构。

> **AI**：这题答太短，可以主动补："核心是 self-attention + position encoding + feed-forward + residual/layer norm。相比 RNN，它能并行建模序列中任意 token 的依赖关系。"

### Q8. 为什么 Transformer 适合 LLM？

这个问题可能要从 LM 本来那几个模型缺陷说起。一开始用卷积神经网络，它不太适合大语言模型，因为大语言模型的序列长度是不固定的。后来又用了 LSTM 这种长短遗忘门，本质上还是为了建立序列信息。

Transformer 架构本身将整个句子都可以放进去，然后每一个 token 都会有对应的 QKV 矩阵。这样每一个词都能看到这个词对前面所有单词的响应概率或者相关度，天然形成了一个可以看到整个序列的架构，所以 Transformer 很适合做大语言模型。

> **AI**：方向对，但要更准。Decoder-only LLM 通过 causal mask 只能看当前位置之前的 token，不是任意看未来 token。Transformer 适合 LLM 的关键是：self-attention 能直接建模长距离依赖；训练时比 RNN 更容易并行；规模化后符合 scaling law；decoder-only + causal LM 目标天然适合 next-token prediction。

### Q9. Transformer 和 RNN/LSTM 在预测下一个词时有什么区别？

我可以稍微说一下。Transformer 现在这个大语言模型就是 decoder-only，去掉了左边的 encoding。我们会输入前面的序列，比如"我喜欢中国"这样的序列，我会先输出"我"，然后屏蔽掉后面的信息。

我前面的问题会提供它的 K 和 V，然后把这个"我"作为 Q 去查询前面跟 K/V 的响应程度。最后经过 MLP 会生成一个 logits，然后再把 logits 通过 LM head 映射回词表，我们就会发现下一个"喜"这个字概率最高。然后把"喜"加上，再在"我喜"继续按照上面的过程重复，把整个序列生成出来，直到碰到终止符号。应该这样是一个过程。

如果是 LSTM 的话，主要是我也没有专门学过 LSTM，只知道概念上的一些问题。所以它暂时应该是通过跟 RNN 类似循环地去做，具体描述过程我暂时描述不出来。

> **AI**：Transformer 生成过程说出了 logits/LM head/逐 token 自回归，这是比上一版更好的地方。但 Q/K/V 描述有点混：每个 token 都会由 hidden state 投影出 Q/K/V，当前位置 query 对历史 token 的 key 做 attention，得到 value 加权和。LSTM 部分没答出来。标准对比：RNN/LSTM 从左到右逐 token 更新 hidden state，历史信息被压缩进状态；Transformer 每层可直接对所有历史 token 做 attention。RNN 难并行、长依赖易衰减；Transformer 训练并行更强，但注意力复杂度 O(n²)。

### Q10. 什么是大语言模型幻觉？

了解过。大语言模型幻觉就是说，大模型会输出一些自己胡编乱造的东西，但它却坚信是对的。这就是通常意义上的大语言模型幻觉吧。

原因的话，我觉得应该跟训练阶段有关系。因为大语言模型总要输出一个东西，它比拒绝回答收益更高，所以大语言模型会倾向于回答，然后确信自己的答案。这样就会产生一些大语言模型幻觉。

> **AI**：回答有直觉，但原因不完整。幻觉的核心是模型在生成高概率文本，不是在查事实数据库；训练目标鼓励流畅续写，不天然保证事实可验证。原因包括训练数据噪声、知识过期、上下文不足、模型过度泛化、解码采样、缺少外部校验。RAG、工具调用、引用 evidence、拒答训练、事实性评估都可以缓解，但不能彻底消除。

### Q11. 看一下课后做的图索引实现效果

上次让我回去在项目上接着做一个知识图谱一样的东西。我先说一下我是怎么做的吧。因为我上次的 RAG 其实已经抽取过 paper ID，包括一些 summary 数据块，所以我就让大语言模型直接根据抽取出来的 paper ID 去构建一个知识图谱。这也是最快的一种方式。

现在查询的时候，我会先用别名或者命名去查询固定节点。比如 Graph RAG 直接就会命中，RAG 也是直接命中。命中之后，我会根据抽取出来的关系最多再进行两跳，看一下它附近的这些概念。比如一跳之后有这些概念，`is_a`、`improve`、`use` 这些概念。每个概念上面都会挂一定量的论文。

除此之外，第一阶段图检索会检索到一些节点，同时还会做之前的密集向量检索。比如这里的虚线就是之前用密集向量检索召回来的块。然后我会把这两个召回的所有候选论文，按照召回排名进行 RRF 混合，最后得到一个最终候选论文结果。之后 compose 阶段就跟之前一样，但是多了一个它可以看我的链路。这里可能没体现，就是可以看到这个图的关系链路，加上候选出来的一些证据块，综合回答最终问题。这就是我做的一个简单 Graph RAG。

> **AI**：这个 demo 方向是对的，而且比口头描述更贴近面试官要求：已有 paper/card/evidence → LLM 离线抽 concept/edge → 在线 seed concept 命中 → 1-2 跳 graph expansion → dense retrieval 并行召回 → RRF 融合 → compose 阶段带 evidence 和 graph path。这里如果再明确一句 "node 是 concept，edge 是 relation，node 挂 paper/evidence"，就非常完整。

### Q12. 蓝色的边是通过什么生成的？边上有哪些属性？

还是通过大语言模型直接看我的 paper card 生成的，因为我之前提取好了。我觉得信息已经高度凝练了。除了自己的节点信息之外，每一个节点后面会跟一些边的信息。从这个边出来，这个边的信息就是"是什么"、"improve 了什么"、"跟什么有关"、`relation_to`、"在什么之上"之类的，就这几条信息。

面试官确认：paper card 会生成若干条边，边之间会有一些名词，也就是点，然后按照点聚集一下，重建这棵树，蓝色边是这样生成的。

我回答：对。

> **AI**：方向对，但不要说 tree，应该说 graph。概念关系通常不是树，而是多关系、多父节点、可成环的图。边属性可以标准化成：`source`、`target`、`relation_type`、`evidence`、`paper_id`、`weight/confidence`。你现在的关系类型已经有雏形：`is_a`、`improves`、`uses`、`related_to`、`based_on`。

### Q13. 紫色虚线的边是什么意思？

后面这是第二跳的。虚线是用我刚刚说的多路召回，直接搜到证据块里面。证据块里面是有 paper ID 的，然后直接跟这个概念关联上。也就是不是通过图的构造，而是虚线块直接连到后面的论文里。

> **AI**：这个解释挺重要。紫色虚线可以理解为 dense retrieval 召回的 evidence/paper 与 graph concept 的补充连接，不是离线图谱里的结构边。建议面试时把线型语义说清楚：实线是 graph edge，表示概念关系；虚线是 retrieval link，表示这次查询中 dense 召回结果和概念/论文的临时关联。

### Q14. 构图用了多久？token 消耗怎么把控？

这个方面的话，因为我现在已经提取出来很多 paper card 了，而且用的是 DeepSeek V4 的 flash 模型，所以消耗量是很小的。这是第一个成本消耗问题。

第二个时间其实也不长，没有到一个小时，大概四五十分钟就已经提取好了。

> **AI**：回答可以，但还可以更工程化：成本可控的原因是没有把全文丢给 LLM，而是先用 paper card / summary 这种压缩后的中间表示做抽取；每篇论文只抽少量 concept 和 edge；离线一次构建，在线查询复用。这样能把 token 成本、延迟和可复用性都解释清楚。

### Q15. 搜索时怎么保证大模型生成的是图里有的词？有设计吗？

这个主要还是离线部分做的吧。就像你说的，如果大语言模型生成了一些不包含在节点里面的词怎么办？如果有一张地图的话，我就可以往这个地图上面找，它的成功率就会比较高。

但是我还没开始做，主要还是依赖于离线提取的别名数，尽量让它丰富一点。这样各种中英文还有各种别称都覆盖到，主要是这样做的。

> **AI**：这里是 Graph RAG demo 的弱点之一。你目前主要靠离线 alias 覆盖，缺少 query-to-concept linking。更完整的设计是三级 fallback：① 精确名/别名匹配；② embedding 搜 concept name/description 做近邻匹配；③ LLM 从候选 concept 列表里选择最相关 seed node。这样既不用让 LLM 在全图里自由编词，又能处理用户说法和节点名不一致的问题。

### Q16. 图索引和 embedding 索引哪种好？哪些场景更适合？

确实 Graph RAG 本身成本肯定高。你要对离线关系进行建图，还要大模型去抽。这种场景肯定是在实体关系跳跃比较多的时候。

比如我们组里面就有专门有人会做知识图谱内容，也会研究很多知识图谱算法，所以整体来说还是比较重的一个前面处理过程。这是我从成本方面考虑的。

这样做的话，有些问题是不需要这样做的。只需要得到一些客观事实的话，我直接用 Naive RAG 或者一些强化过的 RAG 就行了，不需要专门去建知识图谱。这个是我觉得它的问题。

> **AI**：回答成熟，承认了 Graph RAG 的成本和适用边界。可以再加正面总结："Graph RAG 适合概念关系、多跳推理、主题扩展和跨论文关联；dense retrieval 适合语义相似、事实定位、原文证据召回。我的设计不是二选一，而是 dense 保底、graph 扩展，最后 RRF 融合。"

## AI 总评

**整体发挥**：训练管线比 PART1 有明显进步，但 LLM 基础仍然不稳。Tokenizer、监督/自监督、Transformer vs RNN、幻觉这些基础题被连续追问，说明面试官在确认你是否适合训练数据系统方向。Graph RAG demo 是加分项，至少完成了课后作业要求，并能讲出多跳扩展、RRF 融合、成本和适用边界。

**得分最高的回答**：

- Q1（训练管线总览）——把预训练、中训练、后训练、RLVR、上线反馈串起来了。
- Q6（SFT vs DPO）——能说出 SFT 学指令，DPO 学偏好，且二者有先后关系。
- Q11（Graph RAG 实现）——讲出了节点命中、两跳扩展、dense + graph RRF 融合、compose 看链路。
- Q16（graph vs dense 场景）——知道 Graph RAG 成本高，适合关系跳跃；普通事实召回 dense 更划算。

**得分最低的回答**：

- Q2（tokenizer）——把 tokenizer 和 embedding layer 的职责混在一起。
- Q5（监督/无监督）——给初中生的例子不够贴切，自监督概念没讲出来。
- Q9（Transformer vs LSTM）——Transformer 自回归讲得比之前好，但 LSTM/RNN 部分仍然答不上来。
- Q15（query-to-concept linking）——Graph RAG 目前主要靠 alias 覆盖，缺少 embedding/LLM fallback 设计。

**这场暴露出的准备方向**：

1. LLM 基础：tokenizer、embedding、position encoding、decoder-only、causal mask。
2. Transformer 基础：Q/K/V、self-attention、RNN/LSTM 区别、并行化、长距离依赖。
3. 训练术语：无监督、自监督、有监督、SFT、DPO、RLVR 的边界。
4. Graph RAG 表达：node/edge/schema/evidence/RRF/fallback/query-to-concept linking。
5. 岗位匹配：飞书这边更像训练数据系统团队，重点不是 Agent 产品，而是训练管线的数据需求、数据合成和评估。

**一句话复盘**：这场不是项目被打穿，而是基础被持续追问。Graph RAG 作业完成度能加分，但如果继续走飞书这个方向，LLM 训练和 Transformer 基础必须补到能随口讲清楚。
