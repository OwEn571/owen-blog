### Q3. 强化学习这块具体做了什么？怎么理解强化学习应用到大语言模型？

好的。强化学习一开始就是基于对一系列动作的奖励嘛，然后去让它可以做出更好的动作轨迹。然后把这个强化学习应用到大语言模型当中，就是希望它输出的一系列 token，将每次输出的 token 都当作一个动作来看，希望它整体的奖励得到更高，然后这样就可以来获得一个更高的分数。

因为以前大语言模型主要训练还是偏向于正确性之类的，而没有偏好方面的这些内容。然后我当时主要研究内容就是对大语言模型做偏好训练。比如说给出一些用户倾向于选择的回答和拒绝的回答，然后就形成了一个 rejected 和 chosen 对。这样的话就可以用 DPO 对模型进行训练，让模型更倾向于输出 chosen 的回答，这样的话就可以做到个性化对齐。

当时是看了一些论文，主要去尝试复现和优化了一个叫 Align-X 的项目。它就是会对很多人进行建模，把一个人的特征建模成 90 个维度，然后在这些维度上，我们去构建每一个维度差别最大的维度，去构建一对 chosen/rejected 对模型进行训练。这样的话就可以选出更符合这个维度的回答。

当时做了一些尝试吧，就是除了它本身来说的话需要一个最标准的 90 个维度才能得到答案，我当时想的是去训练一个方式去更好地预测这 90 个维度。不过最后研究还没出进展，然后就现在先回来接着去看 Agent 后面的比赛项目了。这是之前强化学习做的东西。

> **AI**：Align-X 这个例子是加分的，能证明你不是纯背概念。但"每个 token 都当作动作"略粗糙。更严谨一点：policy 是语言模型，action 可以理解为 token 级生成，也可以把完整 response 看成 action sequence；reward 可以来自奖励模型、规则验证器、人类偏好或任务结果。DPO 不是传统在线 RL，而是用偏好对做离线偏好优化。

### Q4. 除了 DPO，还有其他类似 DPO 的强化学习算法吗？

强化学习是从 Q-learning 一直开始看到最新的 PPO、DPO、GRPO 这一组的。

DPO 相当于说是对 PPO 把它去掉了一个奖励模型嘛，它是把 BT model 反解带入到那个函数当中，让它可以直接去优化最优选择，就不需要去直接算那些东西。

然后 GRPO 的话也是去掉奖励函数，但是它是在同一组中分一个组，然后在当中选出相对优势最好的，就不需要再去专门评估每个绝对分数。

就相当于 DPO 和 GRPO 吧，都是在 PPO 的基础上进行优化。然后后面一些其他更新的优化我就没有看过了。

> **AI**：大方向对，但细节需要改。DPO 不是简单"PPO 去掉 reward model"，而是基于 Bradley-Terry 偏好模型推导出 pairwise loss，直接比较 chosen/rejected 在 policy 和 reference policy 下的 log-prob 差值。GRPO 也不是"去掉奖励函数"，它通常还是需要 reward，只是不训练 critic/value model，而是在同一 prompt 的多条采样里做组内相对 advantage。以后可以补充 ORPO、IPO、KTO、RLOO 这些名字，但不要装细节。

### Q5. GRPO 和 DPO 选出一个或一组之后，更新权值的具体算法了解吗？

GRPO 和 DPO 都是用一个优势函数，然后，等一下我想一下，可能时间有点久。

动作更新的过程中会首先 freeze 一个原本的函数，作为一个原始的参考，防止更新步数过大，然后用 KL 散度做一下约束。然后第二步是每次更新的时候跟前一次更新的结果进行比较，然后用一个学习率乘以一个优势函数，对旧的模型权重进行更新。然后每走一步就更新一下，直到最后更新步数达到了或者是预置达到了你期望的这种奖励分数。

大概看起来就是看过，对吧。

> **AI**：这道题是明显短板。DPO 的核心不是 advantage function，而是 pairwise preference loss；GRPO 才更像用组内 reward 标准化得到 advantage，再带 KL/clip 做策略优化。你说 freeze 参考模型、KL 约束是对的，但"学习率乘优势函数更新旧权重"太泛了。面试官问这个是在看你有没有真正推过 loss，还是只看过概念图。

### Q6. GRPO 有哪些重要超参？分别是什么意思？

GRPO 的话，这个我就是没有自己去训练过，所以我大概只是知道学习率这几个超参。然后其他超参可能还不太了解。没有具体训练过 GRPO。

> **AI**：承认没训练过是对的。需要补的关键词：每个 prompt 采样数 `G`、KL 系数 `beta`、clip range、学习率、batch size、生成温度、最大生成长度、reward 标准化方式、reference model 更新/冻结策略等。明天如果还被问 GRPO，至少要能把"为什么省掉 critic"讲清楚。

### Q7. 整个大模型训练管线有哪些环节？

大模型训练的环节。一开始大模型或者说 base 大模型可能会先做监督微调吧，用一些已经有的知识去训练它对世界的理解。然后就是如果我后面要 SFT 的提升不多，或者说我 SFT 多次回答能达到好结果但是没有排在前面几个，或者不是很倾向于输出，这时候就可以引入强化学习，去让它的回答更好地可以更倾向于输出更好的输出，或者是更符合人类价值观的输出。

然后强化学习之后，可能如果要进行 Agent 发布的话，还要进行一些 Agentic RL 的训练，让模型去尝试理解怎么去调用工具，然后怎么调用工具去理解这些 schema 格式。这是我理解的整个模型训练的过程。

> **AI**：这道题答偏了。你把 SFT 说成了 base 模型早期训练，但面试官马上纠正了：SFT 和 RL 都属于后训练。完整管线应该是：预训练（海量无标注数据，next-token prediction）→ 中训练/继续预训练（领域增强、代码数学、长上下文、多模态等）→ 后训练（SFT、偏好优化、RLHF/DPO/GRPO、安全对齐、工具调用/Agentic RL）→ 评估与数据飞轮。

### Q8. SFT 和 RL 属于后训练，那除了后训练还有什么训练环节？

SFT 和 DPO 属于后训练。一开始我不太了解吧。主要还是后训练这边了解多一点。

> **AI**：这是本场最需要补的点。面试官最后给你的第一个课后作业就是让你系统补：预训练、中训练、后训练、评估体系、数据飞轮。明天不要只背定义，要能说每个阶段的数据、目标函数、产物和评估指标。

### Q9. 体系介绍一下 Agent 领域：组成部分、你做的是哪部分？

好的。Agent 对我来说就是一个大语言模型加上一个，现在来说应该叫 Agent harness 的外壳。当时来说就是一个让大语言模型拥有行动、获取感知环境、再去执行任务的功能。

现在主要是有几种标准的，或者说几种用得比较多的 Agent 模式。比如说 workflow 的模式，我会预先定义好一个运行的管线，然后在其中调用一些大语言模型得到结果，然后按照一个工作流的方式去输出得到的答案。在这种过程中，我可以从中间过程加一些我需要的处理，这样的话可以更好地防止大语言模型胡乱输出，可以让它的输出更加符合我的预期。

另一种比较经典的是 plan and execute 的模式。比如说现在比较流行的这些 coding agent 应该都是这种模式。通过不断执行运行工具，然后返回结果之后，再用大模型继续判断是否要调用模型。这样的话，我们把 bash 的权限给大语言模型，让它不断去 loop 来获得解决问题，最后 Agent 认为解决了问题就会停止。这是目前两个主流的模式。

我做的两个项目也就正好对应这两个模式。一开始做的这个 AIOS 新闻项目，是我第一次接触 Agent 没有多久做的一个工作流项目。目的就是看能不能协调多 Agent 的工作。因为当时做的是一个新闻生产的项目，我就把每个部分的任务交给不同的 Agent 去进行，然后通过写入中间文件这个方法，最后再用 Agent 相互对话去修改一下，让新闻质量更好、更符合预期，最后合并输出整个新闻日报。这是一种标准的 workflow 模式。

最近这个项目做的多模态 Agent 论文应用，是想试一下 execute and planning 的过程。我做的主要就是先初始化，此外还想应用一下 RAG 嘛。然后我对我的本地论文，大概有 100 多篇论文，做了一下离线入库，然后我就尝试用一个 Agent 去输出计划，看能不能多步解决一个关于论文库的问题吧。

> **AI**：这道题是本场发挥比较好的地方。你把 Agent 拆成了 harness + workflow / plan-and-execute 两种范式，还把两个项目分别对应进去。可以再补一个标准组成：LLM、tools、memory/state、planner、executor、guardrail/evaluator、observability。飞书这种办公/数据安全场景应该会很看重可控性和可观测性。

### Q10. 现在 workflow 范式是不是少了？是不是都偏 coding agent 架构？

我认为 workflow 还是有应用场景。就是现在 coding agent 确实用得比较多，但是比较适合那种自由创作，或者想要灵活解决问题这种场景，然后可能是对用户 C 端这边用得比较多一点。

如果要做一个严格交付的流程，比如说我们平时导师会给一些横向，这些都是需要用 workflow 去做的。因为它每一步都需要你严格可追溯，然后也不能出差错，就是输出结果都很固定。

> **AI**：回答稳。更进一步可以说："企业场景通常是 workflow + agentic step 的混合架构，主链路固定，局部步骤让模型动态决策。"这比单纯二分 workflow/coding agent 更贴近真实业务。

### Q11. RAG 入库要切 chunk，你的切 chunk 算法和标准是什么？

我是用 LangChain 的递归切 chunk。因为是中文比较多，切 chunk 之后我先用两次换行作为第一个递归切窗，然后再用一次换行，然后再用空格。这样的话，我设置这个 chunk 的大小大概 1300 左右，overlap 大概 300 左右。这个数字是我在这个范围里试了一下，然后看一下入库速度大概来选择的。就是递归切上的方法。

（补记：中间面试官还问了一次 overlap 的 300 是 token 还是字符，我回答的是 token。）

> **AI**：这里有一个关键纠错：如果你用的是 LangChain 默认 `RecursiveCharacterTextSplitter(chunk_size=1300, chunk_overlap=300)`，并且没有自定义 `length_function` 或用 `from_tiktoken_encoder`，那这里默认单位是**字符数**，不是 token。面试官问这个是在判断你是否真的理解 splitter 参数和 embedding token limit。下次可以补救："我这里默认实现是 character-level splitting，当时口误说成 token；如果要严格对齐 embedding 模型上下文限制，可以改成 tokenizer-aware splitting。"

### Q12. embedding 模型用的什么？

用的 OpenAI 的 text embedding large。

> **AI**：这里应该明确模型全名：`text-embedding-3-large`。如果你实际用的是别的版本，要统一项目文档、简历和口述。

### Q13. 这个 embedding 模型有哪些典型参数？

这个模型，首先一个参数是你切入的到底是 query 还是一个文档这一个参数。然后另一个就是切入维度，需要在 Milvus 中写跟它一样，是 3700 多吧，具体数字当时是看文档的，现在记不清了。

### Q14. Hit、MRR、颜色这些指标当时是怎么测的？

因为这是大概 115 篇自己的论文嘛，然后我就用 AI 给我做了一个 3 级的测试集。因为我这个项目最重要的就是要找到这个论文嘛，所以 Hit@1 应该是最重要。

然后我就会分成每种难度都会写一些题目。比如说第一种难度就是论文题目中就包含我要查的关键词；第二种难度就是论文里面有，但是论文标题没有；第三种是只有论文里面有，但是标题上没有体现出来，比如说 Transformer 这种，Attention Is All You Need 就没有体现 Transformer 这个名词，所以检索的时候应该属于高难度。

然后通过这种方式构建大概 170 多道题吧，就是名词查询的题，然后让它去查询看看最后结果是怎么样的，然后调整我的检索策略。

> **AI**：这是你的强项：有评测集、有难度分层、有 Hit@1/MRR 指标。小问题是数字要统一，一面里你后来确认过实际可能是 159 题，不是 170+。另外 MRR 的解释可以补一句：如果正确论文没排第一，但排在前几位，MRR 比 Hit@1 更能反映排序质量。

### Q15. 如果问题更模糊，标题和正文都没有直接词面，但主题相关，评测集和召回系统怎么设计？

我之前有一些问题比较类似的，比如说我会问，如果我想学习强化学习，我应该看哪些文章这样的开放性题目。

对于测试来说的话，我当时是每个论文都有 paper card，上面会有论文中的关键词。这个关键词不仅包括讨论的专有名词，也包含它所在的一些范畴吧。然后如果这样问的话，我会对论文进行广召回，然后直接看 paper card 里面的范畴。比如说我要看 Agent 的论文，paper card 里面带有 Agent 这种标签的都会被召回。然后第一步就会让大语言模型去判断应该去看哪些论文，再去召回它的正文。

指标方面的话，我应该是会看一下覆盖程度吧，就是我很多论文有 Agent，我看大概能召回多少篇，都覆盖到了没有这样的。

> **AI**：回答思路对，但可以更系统。开放式推荐问题不适合单一 gold paper，可以构建相关集合，评估 recall@k、nDCG、coverage、diversity，再由 LLM judge 或人工给 relevance grade。系统上可以是 query expansion → paper card/topic tag 粗召回 → graph expansion → reranker。

### Q16. 是不是让大模型先生成候选词，再 function call 搜论文，让它自己决策？

对。我现在这个基本上也就是类似于这个思路吧，就是先提取结构化的 target，再去搜论文。

> **AI**：回答太短。更好的表述是："LLM 不直接决定答案，而是把自然语言 query 转成结构化检索计划，比如 target concept、paper constraints、question type、是否需要图表；检索工具按这个计划召回候选，再由 solver 和 evidence 约束最终答案。"这样更能体现你在做 query planning，而不是把控制权全交给 LLM。

### Q17. 如果今天重新做一版这个系统，会保留哪些设计、推翻哪些设计？

如果要重新做一遍的话，是这样的。我现在论文只有 100 多篇，但是在我的策略之下，我最终还是选择了纯向量检索加上大语言模型重写，一个 query enhancement。

我觉得重做一版，如果我想纳入更多论文或者更大的数据量的时候，我就把这个检索系统给重做一下。我会结合进行 BM25，就是如果词语频数过高的话，我得用一些多路召回去检索，然后再重排一下。这一部分我目前只是在我现在的这个体量下表现的是密集向量检索效果更好。如果重做的话，肯定会用更大规模的数据，然后去换多路检索的方式。

然后保留的肯定是 query 重写的部分，这部分想了很久，然后效果也是挺不错，让大模型重写我的问题里面的关键词。然后另一部分就是 state 结构，结构化地去查询，比我直接去查 query 速度还更快，效果也更好，这是肯定会保留的。大概就是这样。

> **AI**：回答很好。你说出了实验结论的适用边界：小规模 pure dense 效果好，不代表大规模也最佳。可以再补一句：重做时会从"平铺 chunk index"升级成多层索引：chunk index + paper card index + concept graph index。这个正好接住面试官后面的课后作业。

### Q18. 多模态图表公式相关内容，怎么和上下文论文文本关联起来？

这个我其实做了两层的入库。然后图表和论文，我先用 haystack 去查的话，我会先计算每一页的分数。如果图表和表格内容比较大的话，我就从定位它的上下文本，比如说表格和图片下面不都是会有一段文字说明嘛，把它和表格或者图像的位置、页码一起给它嵌入进去。

入库的时候只是对每一页算了一下，用 unstructured 库的 fast 模式判断 PDF 里面的块。如果是图片或表格，我先把这一块内容的 plain text 记录进去，然后页码记录进去。如果召回到这个内容，或者意图识别里面有个参数叫 relation，如果里面大模型给出可能需要查图或查表的话，又召回到了这个图表块的话，再临时把这一页渲染成图片，发给多模态模型让它返回结果。

> **AI**：整体链路讲清楚了：文本/图表元信息入库，召回后回到原页图像做 VLM 解析。这个回答的核心价值在于你没有把图像粗暴塞进普通文本向量库，而是先用 caption/plain text/page 等元信息召回，再在需要时回到原页让 VLM 读图。

### Q21. 调大模型接口时，有哪些参数需要传？格式大概怎么样？

这个了解过。Anthropic 这边的话，我把 system message 作为顶层字段，然后它里面包含一些 context block，里面包含一些对话 system message 和 user message 一对一地出现，然后去把这个东西传给大模型。
